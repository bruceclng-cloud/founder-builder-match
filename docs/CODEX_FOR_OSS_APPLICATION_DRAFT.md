## Short Summary

Founder Builder Match is an open-source prototype for fair founder-builder matching, scoped paid 7-day trial sprints, and proof-of-work records for builders.

## Why It Matters

The project targets a trust gap between:

- people hiring for early software/product projects
- builders who are unemployed, underemployed, or looking for credible project work

Many early collaborations fail because they start as vague networking, unpaid speculative labor, or premature co-founder conversations. This project proposes a reusable open-source workflow:

> good match, fair paid trial, useful proof-of-work.

## Open-Source Ecosystem Role

The project is intended to be reusable infrastructure for:

- startup communities
- university founder programs
- local builder communities
- founder/operator groups
- communities trying to reduce unpaid speculative work

The open-source value is that communities can inspect, adapt, self-host, and improve the matching and trial workflow instead of relying on a black-box marketplace.

## Draft Application Answer

I maintain Founder Builder Match, an open-source prototype for matching people hiring for early software/product projects with builders looking for fair paid trial work.

The project focuses on a specific trust problem: early founder-builder collaboration often happens through vague networking, unpaid speculative work, or premature co-founder conversations. Founder Builder Match proposes a reusable workflow: match on founder need, builder proof, founder seriousness, budget fit, and timezone; then test fit through a scoped paid 7-day trial sprint; then produce a proof-of-work record for the builder.

The project is open source because the workflow should be inspectable and adaptable by startup communities, local founder groups, university entrepreneurship programs, and builder communities. The long-term goal is not just a marketplace, but community-run infrastructure for fair trial collaboration and proof-of-work records.

Codex is already being used to build the prototype, write tests, structure documentation, generate validation workflows, and improve matching logic. Additional Codex support would help turn the static prototype into a functional MVP, add tests for pricing and dispute edge cases, improve security-sensitive proof-of-work and payment-adjacent workflows, and support future community contributors.
